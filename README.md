# Apes Hill Hilltop Villas — Commissioning Site

Live commissioning status for the Apes Hill Hilltop Villas Lutron HomeWorks
takeover (14 villas, Parcel V, St. James, Barbados). Published at
**GitHub Pages** once Settings → Pages is turned on for this repo (see
"Turning the site on" below).

## How it fits together

- **The Google Sheet** (the Apes Hill Hilltop Villas Master Commissioning
  Tracker) is the source of truth for everything except Villa 15's detailed
  technical record and floor plan.
- **`data/villas_extract.json` and `data/villa_issues.json`** are a
  snapshot of that sheet, committed to this repo so the site always has
  something correct to build from, even before live fetching is wired up.
- **`scripts/generate_villas.py`** turns that data into
  `site/villa-{N}/status.html` and `site/villa-{N}/technical-record.html`
  for villas 2, 4, 5, 6 and 7, and writes `data/villas_summary.json` (the
  per-villa stats the fleet dashboard needs).
- **`scripts/generate_fleet.py`** turns `data/villas_summary.json` plus
  Villa 15's and the not-yet-started villas' fixed summaries into
  `site/index.html`, the Fleet Dashboard.
- **`scripts/fetch_sheet_data.py`** pulls fresh data from the live Google
  Sheet via a read-only service account and overwrites
  `data/villas_extract.json` / `data/villa_issues.json` — see "Calibrating
  the live fetch" below before relying on it.
- **`.github/workflows/update-site.yml`** is the "Update Site" button: a
  manually-triggered GitHub Action that runs the fetch (if credentials are
  set) then both generators, then publishes `site/` to GitHub Pages.

Villa 15's `site/villa-15/status.html`, `technical-record.html` and
`floor-plan.html` are **not** regenerated by these scripts — they're a
richer, hand-curated page (keypad engravings, an interactive floor plan)
migrated as-is from the original Claude Artifacts.

## Adding a villa's keypad engravings + floor plan

Confirmed (by diffing Villa 15 against Villa 3) that every villa shares
the exact same construction template: identical floor plan, identical
keypad/load numbering, identical keypad engraving layout, identical load
schedule. So once a villa's Designer Report Package PDF is in hand and
its tracker tab is populated, getting it the same floor-plan treatment is
mostly mechanical:

```bash
python scripts/build_villa_floorplan.py <N> "/path/to/Villa N Report Package.pdf"
```

This reads the villa's own 8 keypad engraving crops straight out of its
PDF (found by scanning its own Table of Contents for where the Engraving
section actually starts — page numbers drift villa to villa, never
hardcode them) and its own pass/pending status from `data/`
(`villas_extract.json`, kept current by `fetch_sheet_data.py`), while
reusing the floor plan's pin geometry (`data/floorplan_pins.json`) and
the engraving/load-schedule layout data verbatim — that part is the same
for every villa and doesn't need re-deriving.

After running it:
1. Add a "Floor Plan" nav button to that villa's `status.html` and
   `technical-record.html` (copy the pattern from Villa 3's).
2. Add the villa number to `REPORT_PACKAGE_PROCESSED` in
   `generate_villas.py`, then re-run `generate_villas.py` and
   `generate_fleet.py` so the fleet dashboard shows its report package
   as Processed.
3. Skim the rendered page once (a couple of keypad/load pins, the
   Garage section) before committing — the script's mechanical, but
   worth a glance, especially if this villa's notes flag anything
   unusual (a wiring anomaly, a layout change) the way Villa 6's North
   Hall issue was flagged.

## Turning the site on

In this repo's **Settings → Pages**, set Source to **GitHub Actions**. The
first successful run of the Update Site workflow (below) publishes the
site and reports its URL.

## Running an update

1. Edit the Google Sheet as usual.
2. Go to this repo's **Actions** tab → **Update Site** → **Run workflow**.
3. Within about a minute the live site reflects the new data.

Until the Google Sheets credentials (below) are in place, running the
workflow still regenerates and republishes the site — just from whatever
is currently committed in `data/`, not a fresh pull from the Sheet.

## Connecting the live Google Sheet

1. In [Google Cloud Console](https://console.cloud.google.com), create a
   project, enable the **Google Sheets API**, and create a service account.
2. Create a JSON key for it (Keys → Add Key → JSON).
3. Share the actual tracker Sheet with that service account's email,
   **Viewer** access.
4. In this repo's **Settings → Secrets and variables → Actions**, add:
   - `GOOGLE_SERVICE_ACCOUNT_JSON` — the full contents of the downloaded key file
   - `GOOGLE_SHEET_ID` — the id from the Sheet's URL (between `/d/` and `/edit`)

## Calibrating the live fetch

`scripts/fetch_sheet_data.py` has not yet run against a real service
account — Step 2 above needs Jeevan's Google account, so it couldn't be
tested while writing it. The per-villa row ranges it reads (checklist,
keypads, closeout, module outputs, lamp dimmers, module registry) are
carried over from the extraction already verified against this sheet, but
the header metadata block and the Issues & Changes tab name
(`ISSUES_TAB` in the script) should be double-checked on the first real
run: diff its output against the `data/villas_extract.json` and
`data/villa_issues.json` already committed here, which are known-correct.

## Local development

```bash
pip install -r requirements.txt
python scripts/generate_villas.py
python scripts/generate_fleet.py
python -m http.server 8000 --directory site   # preview at localhost:8000
```

## Project background

Recommissioning of 14 identical Lutron HomeWorks installations across the
Apes Hill Hilltop Villas development. Each villa's floor plan, keypad
layout and circuit schedule are identical by design — only the
commissioning status, field notes and issues differ per villa.
